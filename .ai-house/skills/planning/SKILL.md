# Planning & Requirements

Before implementation, translate the request into observable behavior.

- Identify the user, problem, expected outcome, constraints, and non-goals.
- Inspect the existing implementation before suggesting a new architecture.
- Write concise acceptance criteria that can be verified.
- List likely files/modules, dependencies, migration needs, risks, and edge cases.
- Identify ambiguity. Ask only questions that block a safe or correct implementation; otherwise document assumptions.
- Keep scope proportional. Separate required work from optional improvements.
- For larger work, use a short ordered checklist and update it as work proceeds.
