# Documentation

- Keep docs aligned with actual commands, configuration, behavior, and limitations.
- Prefer concise, task-oriented setup and troubleshooting steps.
- Do not document unimplemented features as available.
- Never include secrets, private customer data, or real credentials in examples. Use clearly fake placeholders.
- Update the most relevant existing document rather than creating redundant documentation.
- Verify example commands where practical and label environment-specific assumptions.
